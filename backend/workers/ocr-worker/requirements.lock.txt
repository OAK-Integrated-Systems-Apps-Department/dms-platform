# Full transitive dependency lock for ocr-worker, generated via
# `pip freeze` against a known-working install (the running oakdms-ocr-worker
# container) -- see Dockerfile's build stage, which installs from this file
# as a constraints file (`pip install -c requirements.lock.txt .`) so a
# future rebuild resolves the exact same versions instead of re-resolving
# pyproject.toml's floor (">=") constraints fresh against whatever is
# currently on PyPI. This is what pyproject.toml's own comment on the
# docling/paddleocr/paddlepaddle pins refers to as "the actual
# reproducibility guarantee for the full dependency tree" -- those three are
# pinned by hand there because they're the ones with a known history of
# breaking output-format changes between major versions; this file locks
# everything else transitively too, so no dependency (a docling-core/
# paddlex/transformers point release, etc.) can silently change shape on a
# rebuild the way paddleocr 2.x -> 3.x already did once (see ocr_engine.py's
# own doc comment).
#
# torch/torchvision are deliberately NOT listed here: they're installed by
# a separate, earlier RUN step from PyTorch's own CPU-only wheel index
# (see Dockerfile's own comment on why), and that index doesn't serve the
# same package names/versions plain PyPI does -- listing their "+cpu"
# version here would break resolution against the default index this file
# is otherwise installed against.
#
# To regenerate after intentionally changing a dependency: rebuild the
# image, then `docker exec <container> pip freeze`, filter out the
# `ocr-worker @ file:///build` self-reference line and any torch/
# torchvision lines, and replace everything below.
